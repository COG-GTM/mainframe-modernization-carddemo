# Modern migration of CBACT01C

Java 17 equivalent of the batch program [`app/cbl/CBACT01C.cbl`](../app/cbl/CBACT01C.cbl):
read the account master file sequentially and print every account record.

## Program mapping

| COBOL | Java |
| --- | --- |
| `CBACT01C` procedure division, `0000-ACCTFILE-OPEN`, `9000-ACCTFILE-CLOSE` | `Cbact01c.run` |
| `1000-ACCTFILE-GET-NEXT` (sequential read of the `ACCTFILE` KSDS) | `AccountFileReader` |
| `1100-DISPLAY-ACCT-RECORD` | `Cbact01c.displayAccountRecord` |
| `9910-DISPLAY-IO-STATUS`, `9999-ABEND-PROGRAM` (`CEE3ABD`, code 999) | `AbendException` |
| copybook `CVACT01Y` (`ACCOUNT-RECORD`, RECLN 300) | `AccountRecord` |
| zoned decimal `PIC S9(10)V99` fields | `CobolDecimal` + `java.math.BigDecimal` |

### Data types

Amounts keep the COBOL picture exactly: `BigDecimal` with scale 2, twelve digits,
never a `double` or `float`. `ACCT-ID` stays a string so the eleven digit key keeps
its leading zeros, matching `PIC 9(11)`.

Sign handling covers both conventions found in CardDemo data: the EBCDIC extract
overpunches the last digit (`{ABCDEFGHI` positive, `}JKLMNOPQR` negative) while the
ASCII runtime writes positives as plain digits. Both parse; serialization writes the
ASCII convention, which is what the COBOL runtime itself writes back.

## Running

```bash
mvn -f modern/pom.xml test
mvn -f modern/pom.xml package
java -cp modern/target/classes com.cog.carddemo.Cbact01c app/data/ASCII/acctdata.txt
```

## Equivalence testing

`Cbact01cEquivalenceTest` compares the Java report byte for byte against the output of
the COBOL program itself over the 50 sample accounts in
[`app/data/ASCII/acctdata.txt`](../app/data/ASCII/acctdata.txt).

The baseline `src/test/resources/golden/CBACT01C.expected.txt` is generated by
[`tools/generate_golden.sh`](tools/generate_golden.sh), which compiles
`app/cbl/CBACT01C.cbl` with GnuCOBOL and runs it. Because `CBACT01C` reads an
`ORGANIZATION IS INDEXED` dataset, the helper program [`tools/LOADACCT.cbl`](tools/LOADACCT.cbl)
loads the ASCII extract into an indexed file first, the equivalent of the `IDCAMS REPRO`
step of the mainframe job.

Regenerate the baseline after any change to the COBOL program or the sample data:

```bash
sudo apt-get install -y gnucobol
modern/tools/generate_golden.sh
```

`AccountRecordTest` additionally asserts field level fidelity: every sample record
round trips through `AccountRecord` unchanged except for the positive sign overpunch
normalization that the COBOL runtime also performs.
